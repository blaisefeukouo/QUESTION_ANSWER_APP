Alfred: Hi, can you explain to me how compression works in MongoDB? 
Bruce: Sure! MongoDB supports compression of data at rest, It uses either zlib or snappy compression algorithms at the collection level. When data is written, MongoDB compresses and stores it compressed. 
        When data is read, MongoDB uncompresses it before returning it. Compression reduces storage space requirements. 
Alfred: Interesing, that's helpful to know. Can you also tell me how indexes are stored in MongoDB? 
Bruce: MongoDB indexes are stored in B-trees. The internal nodes of the B-trees contains keys and pointers to child nodes, while the leaf nodes contain the actual index keys and references to the documents. 
        This structure allows for efficient searching, insertion, and deletion operations with logarithmic time complexity. 
Alfred: That makes sense. Are there different types of indexes in MongoDB? 
Bruce: Yes, MongoDB supports several index types including single field indexes, compound indexes, multikey indexes for arrays, text indexes for text search, geospatial indexes for location data, and hashed indexes for sharding. 
        Each type is optimized for different query patterns.
